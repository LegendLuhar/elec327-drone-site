Project Overview

ELEC 327 — FINAL

A custom bare-metal flight controller for a micro-whoop class quadcopter — every line of firmware written from scratch against the bare silicon, every trace routed by hand.

// Course. ELEC 327 (Digital Systems Lab) at Rice — bare-metal embedded with hard real-time timing requirements. Final project, single semester.

// Build. 4-layer custom PCB integrating MCU, 6-DoF IMU, power regulation, radio interface, and a 4-in-1 ESC connector. Every component soldered directly — no breakout boards, no dangling wires.

// Scope. v1 is intentionally minimal: gyro sampling, DShot ESC output, CRSF radio input parsing. USB, OSD, blackbox logging, and GPS are deliberately excluded — unnecessary for micro-whoop class and outside the timebox.

// Tone. Engineering rigor over flight hours. The deliverable is the bring-up — register-level debug, cycle-accurate bit timing, two characterized silicon-level bugs. Motors didn't spin (ESC hardware fault, diagnosed), but the firmware bring-up is complete.

Firmware Architecture

933 SLOC · 6 MODULES · 0 EXTERNAL DEPS

Bare-metal C against the MSPM0 silicon. No HAL, no RTOS, no external frameworks — just a linker script, an ISR vector, and direct register manipulation. Written in TI Code Composer Studio, structured around four drivers and two bring-up mains. Every volatile in the project is reachable from a CCS Expressions watch — debug is over SWD, not over print.

dshot.c / .h DRIVER
DShot300 · 4 motors · DMA-driven timer PWM. TIMA1 covers M1+M2, TIMG8 covers M3, TIMA0 covers M4 — all sourced from TIMA1's Z event.
imu.c / .h DRIVER
ICM-42688-P over SPI1. Soft-reset → WHO_AM_I=0x47 → gyro+accel low-noise. Polled 14-byte burst at 1 kHz.
pwm.c / .h FALLBACK
50 Hz servo PWM, 1000–2000 µs. Same pin assignment as DShot, no DMA. Abandoned for bring-up; kept compilable.
delay.c / .h UTIL
Cycle-accurate busy-wait. TI BSD-3 reproduction; only third-party code in the tree.
dshot_test.c MAIN
Active bring-up main. 10 kHz scheduler, staged diagnostic (arm → beep-sweep → spin-sweep → all-spin), plus PIN_WALK_TEST macro for SWD-readable pad sanity check.
pwm_test.c EXCLUDED
Alternate main using pwm.c. Built to bisect “motors won't spin” into MCU-vs-ESC. Currently excluded from build.

DMA + Event Fabric

The MSPM0's event fabric is an on-chip publish/subscribe bus — peripherals broadcast events onto numbered channels; other peripherals subscribe. We wired four DMA channels to a single timer event for zero-CPU motor transmits.

Debug Log

03 BUGS · ALL FIXED 2026.05.15

Three genuine silicon-level bugs surfaced during DShot bring-up. All required SWD-attached register inspection to characterize — no oscilloscope, no logic analyzer. The debugging methodology is the methodology: every volatile is in an Expressions watch, every fault is a hypothesis ratified by a counter that does or doesn't climb.

BUG · A FIXED

Missing CCPD Register Configuration

SYMPTOM
Lines effectively Hi-Z during DShot transmits — ESC saw nothing on the wire.
ROOT CAUSE
Every GPTimer has a Capture/Compare Pin Direction (CCPD) register that defaults to INPUT on reset. The compare engine was configured correctly, but the pad multiplexer was never told to route timer output to the pin.
FIX
Explicit read-modify-write to set CCPD to OUTPUT per channel before any transmit attempt.
BUG · B FIXED

Trailing-HIGH Idle Between Frames

SYMPTOM
BLHeli_S played its lost-signal chime forever even though every frame appeared correct on the wire. ESC never armed.
ROOT CAUSE
Original dshot_transmit() left the line HIGH for ~43 µs after every frame — the timer's post-bit QUIET period. Some BLHeli_S decoders refuse to lock if idle isn't actually idle.
FIX
dshot_transmit() now blocks ~56 µs for DMA completion, then re-mux's the pins to GPIO PF=1 driving LOW. Every frame ends with a clean falling edge.
BUG · C FIXED

DMA-Enable / Z-Event Race on Bit 15

SYMPTOM
10–20% of frames silently lost bit 15, failed CRC, and were rejected by the ESC. Intermittent — impossible to catch on a scope without statistical capture.
ROOT CAUSE
Old order was: enable DMA → clear RIS.Z → wait for Z. A Z pulse landing in the ~5-cycle window between enable and clear caused DMA to silently consume bit 15, then the CPU spin-wait caught bit 14's Z and flipped pins one bit late.
FIX
Two-stage Z sync. Spin once to land at a known counter position, then ack + enable DMA inside the post-Z quiet window, then spin again — the second Z is guaranteed to be the same one DMA fires on. Worst-case spin: ~6.6 µs.

/ 06 — BIT TIMING DSHOT300 PROTOCOL

Cycle-accurate at 16 MHz.

Each motor pin is driven by a timer compare-match. The whole bit period is 53 ticks long at 62.5 ns each — a '1' holds the line HIGH for 39 of those, a '0' for 19.

/ LOAD 53 ticks Period ≈ 3.31 µs → 300 kbit/s
/ BIT1 HIGH 39 ticks ≈ 2.44 µs
/ BIT0 HIGH 19 ticks ≈ 1.19 µs
/ FRAME 16 bits 11 throttle + 1 telem + 4 CRC
/ BUFFER 17 halfwords 16 bit-CCs + 1 trailing QUIET
/ IDLE GPIO LOW Pins re-mux'd to PF=1 between frames
/ 07 — DEBUG LOG 03 BUGS · ALL FIXED 2026.05.15

Three silicon-level bugs, no scope.

Every fault diagnosed through SWD-attached register inspection. The methodology: form a hypothesis, watch a counter, ratify or reject.

BUG · A
CCPD default = INPUT
Every GPTimer's per-pin direction register defaults to INPUT on reset. Compare engine ran, pad mux stayed disconnected. Fix: explicit OUTPUT in dshot_init_one_timer().
BUG · B
Trailing-HIGH idle
Line stayed HIGH ~43 µs after every frame. BLHeli_S refused to lock onto a non-idle idle. Fix: re-mux pins to GPIO LOW after DMA completion.
BUG · C
DMA/Z race on bit 15
~5-cycle window between DMA-enable and Z-clear caused 10–20% of frames to silently consume bit 15. Fix: two-stage Z sync.
